# بسته درخواست مدرک برای کلاس «گزارش/کاربرگ دوره‌ای پیشرفت Project Controls»

این بسته فقط برای همین کلاس انتخاب‌شده معتبر است:

- پروژه: مارون
- کلاس منبع: گزارش/کاربرگ دوره‌ای پیشرفت Project Controls
- دامنه facts مجاز:
  - دوره گزارش
  - Plan گزارش‌شده
  - Actual گزارش‌شده
  - شاخص پیشرفت گزارش‌شده
  - وضعیت فعالیت گزارش‌شده
  - milestone گزارش‌شده
  - مسئله/محدودیت Project Controls که صرفاً به‌صورت گزارش‌شده ثبت شده باشد

این بسته برای این موارد **نیست**:

- تأخیر قراردادی
- claim / entitlement
- وضعیت یا مجوز پرداخت
- مسئولیت مالی
- نتیجه‌گیری حقوقی
- تأیید ایمنی یا compliance
- خاتمه نهایی پروژه
- اعلام «آخرین وضعیت فعلی پروژه»
- reliance eligibility
- insurance / guarantee semantics

---

## فرم ۱ — تأیید مرجع حاکمیتی

این فرم باید توسط کسی تکمیل شود که واقعاً اختیار تصویب scope حاکمیتی این pilot را دارد.

### سؤال

چه نقش سازمانی مجاز است scope حاکمیتی این pilot را برای کلاس
«گزارش/کاربرگ دوره‌ای پیشرفت Project Controls» تصویب کند؟

### موارد موردنیاز

- نام و نام خانوادگی امضاکننده
- سمت سازمانی
- نقش حاکمیتی تأییدشده
- مبنای اختیار
  - مثل ابلاغ، چارت مصوب، delegation، مصوبه، charter
- تاریخ اثر
- تاریخ انقضا اگر دارد
- روش تأیید
  - نامه، سامانه رسمی، امضای دیجیتال، فرم مصوب

### خروجی قابل‌قبول

یک سند کنترل‌شده یا تأیید امضاشده که صریحاً مشخص کند این نقش
اجازه تصویب همین scope را دارد.

---

## فرم ۲ — تأیید مسئولیت Project Controls / PMO

این فرم باید توسط کسی تکمیل شود که به‌صورت رسمی از مسئولیت‌های
Project Controls / PMO در پروژه مارون اطلاع سازمانی معتبر دارد.

### سؤال

کدام نقش سازمانی مسئول رسمی تهیه/کنترل همین کلاس گزارش/کاربرگ
دوره‌ای پیشرفت پروژه مارون است؟

### موارد موردنیاز

- نام و نام خانوادگی امضاکننده
- سمت سازمانی
- نام نقش مسئول
  - Project Controls / PMO یا معادل رسمی آن
- دامنه پروژه
  - باید صریحاً مارون را پوشش دهد
- توضیح مسئولیت
  - تهیه، کنترل، انتشار، یا مالکیت همین کلاس گزارش
- تاریخ اثر
- روش تأیید

### خروجی قابل‌قبول

یک سند کنترل‌شده یا تأیید امضاشده که مشخص کند این نقش
برای همین کلاس گزارش در همین پروژه مسئول رسمی است.

---

## فرم ۳ — تعریف کنترل‌شده‌ی کلاس گزارش/کاربرگ

این فرم باید توسط مسئول رسمی Project Controls / PMO یا مسئول کنترل اسناد
برای همین کلاس گزارش تکمیل شود.

### سؤال

برای همین کلاس «گزارش/کاربرگ دوره‌ای پیشرفت Project Controls»،
دوره گزارش دقیقاً کجا تعریف می‌شود و convention کنترل/انتشار آن چیست؟

### موارد موردنیاز

- نام کلاس گزارش/کاربرگ
  - نه لزوماً نام فایل
- نقش مالک سازمانی
- نوع محل/سامانه نگهداری
  - بدون افشای مسیر محرمانه
- محل قطعی ثبت دوره گزارش
  - header
  - field مشخص
  - document-control metadata
- قاعده شناسایی نسخه / revision / document number
- قاعده release / approval / issue
- تاریخ اثر
- روش تأیید

### نکته بسیار مهم

برای این کلاس، این موارد **business time معتبر نیستند**:

- تاریخ فایل
- زمان acquisition
- تاریخ‌های row-level برنامه‌ای

business/reporting time فقط باید از یکی از این دو منبع بیاید:

- header دارای reporting week / reporting period
- field رسمی و مشخص reporting period

### خروجی قابل‌قبول

یک سند کنترل‌شده یا تأیید امضاشده که برای همین کلاس گزارش،
محل دقیق دوره گزارش و convention کنترل/انتشار را روشن کند.

---

## چهار ورودی اضافی لازم برای ثبت منبع واقعی

بعد از تکمیل سه فرم بالا، برای register کردن source واقعی همین کلاس،
این چهار ورودی هم لازم است:

1. شناسه پایدار source/system
2. نوع source برای همین workbook/report class
3. توصیف غیرمحرمانه محل/سامانه
4. نقش مالک منبع

---

## نتیجه مورد انتظار پس از دریافت مدارک

اگر این مدارک واقعی و قابل‌راستی‌آزمایی ارائه شوند، سیستم فقط می‌تواند:

- readiness را برای همین کلاس ارزیابی کند
- source واقعی را register کند
- native acquisition و policy evaluation را برای همین scope آماده کند

حتی در آن حالت هم این‌ها **خودکار فعال نمی‌شوند**:

- certification
- current status assertion
- reliance eligibility
- insurance semantics
